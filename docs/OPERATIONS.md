# Operations

Aura runs at `/aura/` behind shared ServerPortal device authentication and listens on `127.0.0.1:18087`. The runtime user is `aura`; restricted deployments use `aura-deploy`. GitHub repository: `Crashmere/Aura` (public), including public Apple-client installers. Do not publish the server address, credentials, originals, databases, or backups.

## Runtime and layout

| Path | Purpose |
| --- | --- |
| `/opt/aura/bin/aura` | Embedded-web Go program, including the generated Mac-client ZIP |
| `/opt/aura/bin/deploy-{ssh,release}.sh` | Root-maintained restricted release entry points |
| `/opt/aura/config/` | systemd units, Nginx location, Portal declaration and source receipt |
| `/opt/aura/data/aura.sqlite` | Catalog, upload state, source observations, durable media jobs |
| `/opt/aura/data/assets/` | Immutable SHA-256 originals |
| `/opt/aura/data/derived/` | Rebuildable JPEG/MP4 previews; excluded from backups |
| `/opt/aura/data/incoming/` | Uncommitted resumable uploads; excluded from backups |
| `/opt/aura/data/work/` | Temporary decoder material; excluded from backups |
| `/opt/aura/backups/` | Consistent database and original snapshots |
| `/opt/aura/releases/` | Programs, hashes, release results and rollback records |
| `/opt/aura/docs/` | Synchronized maintenance documentation |

Go and Node are build dependencies on the maintenance computer only. Production uses official Ubuntu `libvips-tools`, `libheif-plugin-libde265`, `libimage-exiftool-perl`, and `ffmpeg`. Native libraries process files as the unprivileged application user. The service uses persistent disk for work files rather than `/tmp` capacity. TZ is `Asia/Shanghai`; update the unit for a different default interpretation of timezone-free capture dates.

## Initial installation

Use server-operations, explicitly read `/opt/AGENTS.md`, and check the whole inventory and live port allocation. This installation creates only the new application's identities, units, directories, and Nginx location. It inherits the shared authentication include and does not replace the shared Nginx server.

Build on the maintenance Mac, transfer the verified Linux binary, `deploy/`, and the existing deployment public key into a private staging directory, then run as administrator:

```sh
bash deploy/install.sh ./aura-linux-amd64 ./deploy-public-key.pub
```

The script requires an absent `/opt/aura`, empty application identity names, a free port, installed media tools, the shared backup lock, and ServerPortal. It explicitly initializes a new empty library, configures a restricted forced-command deployment account, starts the service/timer, takes the first backup, checks Nginx syntax, and adds the application location. Register the declaration through the normal release protocol afterward; do not start with real photos in a synthetic validation directory.

The only anonymous application resources are exact GET/HEAD requests for `favicon.svg` and `apple-touch-icon.png`. The PNG is an opaque 180×180 image generated by `scripts/icons.sh`. Mac downloads, JavaScript, pages, APIs, and media stay authenticated. No custom `add_header` overrides the shared cookie-renewal header.

## Release

Validate the affected behavior locally, commit and push `main`, then run:

```sh
make release
make deploy
```

The shared release tool exports the pushed commit, installs locked web dependencies, compiles the Mac client on the maintenance Mac, embeds the frontend/client archive, and builds a static Linux amd64 executable. Provenance and SHA-256 are retained under `.local/releases/<commit>/`. The fixed server script accepts only the program and validated Portal declaration, uses the old program to snapshot data, checks the candidate against that snapshot as `aura`, replaces the binary atomically, and checks direct plus proxied health. Program failure restores the previous program. Schema/data recovery is separate.

Use `make portal` for declaration-only changes. `make rollback COMMIT=<full-compatible-commit>` reuses a locally retained program through the same guarded flow. The initial catalog schema is version 1; verify compatibility before any future schema-affecting rollback.

Apple-client installation publication follows [Client Releases](CLIENT-RELEASE.md). Relevant client-source pushes build the Mac DMG and iOS IPA in GitHub Actions and publish the next version automatically. This workflow has no server access; `make deploy` continues to be a maintenance-computer operation.

`deploy/portal.json` is the source for resource browsing, original/derived distinctions, API inventory, port, units, and backup contract. Registration creates `/opt/serverportal/registry.d/aura.json` and verifies the loaded declaration hash. Project/shared documentation changes require a subsequent `sync-docs.sh shared Aura` from the pushed agent-config checkout.

## Backups and recovery

The daily timer runs at 04:35 Asia/Shanghai with up to two minutes of jitter and retains the latest 14 completed `daily-YYYYMMDD-HHMMSS` snapshots. Its unit holds the shared retention lock. Native snapshots contain a `VACUUM INTO` database image, hard links to every referenced immutable original, and a manifest containing SHA-256 for the database and every original. A filesystem without hard-link support uses an independent file copy. Originals are never modified in place, so hard-link snapshots remain stable.

```sh
aura backup --data /path/to/data --out /path/to/new-snapshot
aura verify-backup --source /path/to/snapshot --full
aura restore --source /path/to/snapshot --out /path/to/new-data
aura check --data /path/to/new-data
```

Backup and restore destinations must not already exist. A `.part-<id>` staging directory becomes the final snapshot only when complete. Full verification checks SQLite integrity, database/manifest agreement, byte counts, and every original hash. Restore always targets a new directory; it never overwrites the live library. Derived previews regenerate on access/retry, and incomplete uploads must be resumed from the client's original files.

The manifest also follows the shared media-backup contract (`version:1`, `files:{relative-path:sha256}`), so existing Portal packaging and release retention can validate it without a new adapter. Portal recovery packages include native snapshots and runtime/configuration materials while excluding declared caches. Shared release retention retains the latest three successful programs and five completed before-deploy snapshots plus protected versions. Manual snapshots are not rotated by Aura.

The existing host cloud-backup service is independent of Aura. Completed native snapshots provide consistent recovery points; cloud-side billing, retention changes, and recovery are managed through the shared server workflow. No additional backup vendor or paid service was introduced.

For migration, pause clients, take and fully verify a final snapshot, transfer it preserving bytes, restore into a new directory on the destination, install media runtimes, and start a matching program behind the new authenticated proxy. Verify catalog counts, a Live Photo, original checksums, backup execution, and authenticated download behavior before switching clients. Retain the old recovery point until the migrated library is accepted. Real-data replacement and recovery-point selection require the established server authorization workflow.

## Diagnostics

```sh
systemctl status aura aura-backup.timer
journalctl -u aura --since today
curl --fail http://127.0.0.1:18087/healthz
systemctl start aura-backup.service
systemctl show aura-backup.service -p Result -p ExecMainStatus
```

`GET /api/jobs` and the upload dialog show failed previews separately from accepted originals. Check installed decoders and the journal, then retry the affected file. RAW files without a supported full decoder can use their embedded JPEG preview. A missing derivative is disposable; a missing original is a recovery problem and must not be hidden by creating a new empty catalog.

Use the shared `view-tunnel.sh` for read-only production browser checks. Run shared icon, authentication-boundary, and cookie-renewal checks when changing proxy rules. Test uploads, merges, and recovery only in isolated libraries; production acceptance does not add synthetic photos.
